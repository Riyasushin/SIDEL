# SWE-bench Lite Dev Snapshot

This directory contains the fixed 23-task SWE-bench Lite dev snapshot and the prompt template used by the manager. The current runner is not the old baseline script stack; experiments are planned through `python3 -m manager.cli` and executed inside official SWE-bench task images with Codex or Claude layered in through a wrapper image.

## Files

```text
bench/
├── swe_lite_dev_23.jsonl
└── prompts/
    └── solve_issue.md
```

The prompt template receives only SWE-bench task fields. Router mode, dataset sample, injection turn, and API keys live in manager manifests and the shared-router registry; they are not inserted into the task prompt.

## Typical Workflow

Fetch or refresh the task snapshot when needed:

```sh
python3 scripts/swebench_fetch_tasks.py
```

Build the router/agent tool image:

```sh
docker compose build
```

Plan a small replay-injection run against one task and three dataset samples:

```sh
python3 -m manager.cli plan \
  --run-id smoke-inject-2419-samples1-3 \
  --instance-id sqlfluff__sqlfluff-2419 \
  --samples 1:3 \
  --agents codex \
  --router-mode replay-inject \
  --injection-turns 0 \
  --trace-source-root artifacts/runs/recordings
```

Render container commands without running the agent:

```sh
python3 -m manager.cli run-containers \
  artifacts/runs/smoke-inject-2419-samples1-3 \
  --router-url http://router:8000 \
  --dry-run \
  --build-images
```

Summarize context-level results:

```sh
python3 -m manager.cli analyze artifacts/runs/smoke-inject-2419-samples1-3
```

## Preflight

Run the project preflight before a real batch:

```sh
scripts/swebench_preflight.sh
```

It checks key configuration, Docker availability, the local `code-agent-router:local` image, the 23-task manifest, syntax compilation, and unit tests. Real router proxy runs require `KIMI_API_KEY` in the environment or ignored `.env`; per-container router API keys are generated by the manager and stored raw only in `router/effective_config.json`.
